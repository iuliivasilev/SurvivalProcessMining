# Поиск предвестников отказа

Алгоритм ищет события и цепочки, которые чаще встречаются перед заданным отказом, чем в сопоставимых фрагментах без отказа. Он сравнивает две группы окон, строит взвешенный граф событий и ранжирует кандидатов.

**Схема:** выбор условного якоря → подбор контроля без отказа → временное затухание и Conditional Lift → обратный PageRank → поиск и проверка полных цепочек.

## Как работает алгоритм

На вход подаётся CSV с временем, типом события и идентификатором полного цикла. В примере это столбцы `t`, `event`, `case`; целевое событие — `F`. Записи группируются по циклам. В цикле с отказом используются только события строго перед первым `F`; полностью наблюдённые циклы без `F` образуют контрольную группу.

Например, одна из сопоставляемых пар может выглядеть так:

```text
Отказ:    S → C → P → A → F
Контроль: S → C → B → A → OK
```

### 1. Выбор условного якоря

Алгоритм перебирает типы событий перед `F`. Для каждого кандидата `A` он берёт последнее допустимое появление перед отказом и проверяет, можно ли найти контрольные циклы с таким же событием. Приоритет получает кандидат, позволяющий сопоставить больше циклов с отказом; далее учитываются число контролей и временная близость к цели.

Выбранный якорь служит общей точкой выравнивания. В примере обе последовательности сопоставляются по `A`.

### 2. Подбор контроля без отказа

Для каждого окна с отказом ищется контроль с тем же якорем. Предпочтение отдаётся окнам с близким числом событий и близким положением якоря относительно начала цикла. Если заданы дополнительные поля сопоставления, например имя компьютера, их значения должны совпадать.

В контроле задаётся условный момент результата: расстояние от `A` до него равно расстоянию от `A` до `F` в парном цикле. Так задаются сопоставимые интервалы относительно якоря; история каждого окна ограничена началом его цикла. Один контрольный цикл не используется повторно.

### 3. Временное затухание и Conditional Lift

В каждом окне соединяются пары событий, если второе произошло позже первого и интервал не превышает заданный предел. Между ними могут быть другие записи. Чем меньше интервал, тем больше временной вес:

```text
time_weight = 2 ** (-delta / half_life_seconds)
```

Для каждой связи подсчитывается число окон с отказом, где она присутствует (`SD`), и взвешенная поддержка в контроле (`SO`). С учётом сглаживания `a` и одинакового суммарного веса двух групп:

```text
Lift = (SD + a) / (SO + a)
edge_weight = sum_time_weights / N * max(1 - 1 / Lift, 0)
```

Здесь `N` — число сопоставленных окон с отказом. Повторения одной связи внутри окна дают одно подтверждение; используется её максимальный временной вес в этом окне.

Если связь одинаково распространена в обеих группах, её Lift равен 1 и вес обнуляется. Если она чаще встречается перед отказом, получает положительный вес. Это уменьшает влияние общих фоновых связей, например между событиями, регулярно присутствующими в обоих типах циклов.

### 4. Обратный PageRank

Из положительных связей строится граф. Для ранжирования исходные входящие рёбра цели заменяются служебным соединением `A → F`; сохраняются узлы, из которых можно дойти до цели через якорь.

PageRank рассчитывается на обратном графе с персонализацией на `F`: вес распространяется от цели через якорь к предшествующим событиям. В результате каждый кандидат получает относительный ранг с учётом связей во всём оставшемся графе. Якорь и цель не включаются в список ранжируемых кандидатов.

### 5. Поиск и проверка полных цепочек

Алгоритм постепенно расширяет цепочки от цели к более ранним событиям, сохраняя лучшие продолжения ограниченным лучевым поиском. Повторяющиеся узлы внутри цепочки не допускаются. Оценка объединяет веса связей и нормализованные ранги их исходных узлов:

```text
chain_score = geometric_mean(edge_weights) * mean(normalized_PageRank)
```

Служебное соединение `A → F` в эту оценку не входит. Затем каждая цепочка проверяется в исходных окнах: все её события должны встретиться в правильном порядке, с допустимыми интервалами и с тем экземпляром якоря, который был выбран для окна. Так исключаются цепочки, собранные из рёбер разных циклов, но нигде не встречавшиеся целиком.

Для прошедших проверку цепочек сохраняются поддержка в обеих группах, Lift и итоговая оценка. Например, результатом может стать `P → A → F`.

## Запуск

Проверено на Python 3.12. Из каталога проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python precursor_mining.py --config config/example.json --output results/demo
```

Пример — небольшой искусственный журнал: три цикла с отказом и три без отказа. Ожидаются статус `ok`, якорь `A`, три сопоставленные пары и первое место `P` среди кандидатов. В `paths.csv` первая цепочка — `P → A → F`, её поддержка равна 3 в окнах с отказом и 1 в контроле, Conditional Lift = 2. Это проверка работы программы, а не оценка качества на независимых данных. События `C` и `S` также могут попасть в ранжирование через связи с `P`; их ранг не означает самостоятельного вклада в отказ.

Для своего CSV измените конфигурацию или передайте `--input`:

```bash
python precursor_mining.py --config config/example.json --input /path/to/events.csv --output results/custom
```

Путь `input` в JSON задаётся относительно каталога конфигурации, `--input` — относительно текущего каталога. Выходной каталог должен быть новым.

## Основные функции

| Функция | Роль |
| --- | --- |
| `main` | Читает конфигурацию и CSV, запускает анализ, сохраняет файлы. |
| `analyze`, `_cycles` | Формируют циклы, разделяют их по исходу и выбирают якорь. |
| `_match_anchor`, `_window` | Подбирают контроль и выделяют парные окна. |
| `_edge_scores`, `_edge_statistics` | Рассчитывают временные веса, поддержку и Lift связей. |
| `_rank` | Выполняет обратный PageRank, поиск и оценку цепочек. |
| `_occurs` | Проверяет полную цепочку в отдельном окне. |

## Настройка и результаты

Все параметры находятся в `config/example.json`. Основные настройки: столбцы времени, цикла и события; цель `target`; временные интервалы и полураспад веса; число контролей; сглаживание Lift; коэффициент PageRank; глубина и ширина поиска. Значения проверяются классом `Config`.

Результаты: `nodes.csv` — ранги событий; `paths.csv` — цепочки; `edges.csv` — статистика связей; `anchors.csv` и `windows.csv` — выбранные якоря и сопоставления; `summary.json` — конфигурация и статус запуска.

Текущая версия использует один общий якорь и ручные настройки. Полученные оценки выражают статистическую связь с отказом и не являются вероятностью отказа.

Имеющиеся проверки запускаются командой:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest tests -q
```
