# Архитектура survpm

survpm — библиотека для построения и анализа вероятностной сети состояний по журналам событий и измерениям. Она предназначена для разных предметных областей: состояния, исходы и признаки задаются пользователем.

Документ описывает целевую архитектуру. **Существующий API** указан там, где в библиотеке уже есть соответствующая функциональность; остальные имена — предлагаемые интерфейсы.

## Данные и общая схема

```text
Логи и измерения → Сеть → Обученная модель → Генерация / Прогноз
                         ↓                       ↓
                    Визуализация ← Результаты → Метрики
```

Основной объект — `EventLog`:

| Данные | Содержание |
|---|---|
| `events` | `case_id`, состояние `activity`, время `timestamp` |
| `cases` | `case_id` и статические признаки объекта |
| `measurements` | `case_id`, `timestamp`, имя признака `feature`, значение `value` |
| Конец наблюдения | Момент окончания и причина цензурирования, если исход не наблюдался |

Событие фиксирует вход в состояние. Замер X1…X5 может поступить между событиями и сам по себе не является переходом. Сеть допускает циклы и повторное посещение состояний.

**Существующий API:** `survpm.EventLog`, `survpm.read_log(...)`, `survpm.read_csv(...)`, `survpm.prepare(...)`, `survpm.intervals(...)`. Конец наблюдения передаётся через `observation_end`, причина — через `reason`.

## 1. Построение сети по логам

**Вход:** журнал событий, начальные и конечные состояния, правила обработки повторов.

**Выход:** состояния, переходы между ними, начальные и конечные состояния, число наблюдений каждого перехода. Сеть также можно задать вручную.

**Функции:**

| Функция | Вход → выход |
|---|---|
| `discover(log, initial_states, terminal_states)` | Журнал → сеть и статистика переходов. |
| `create_graph(states, transitions, initial_states, terminal_states)` | Списки состояний и рёбер → сеть. |
| `validate_graph(graph)` | Сеть → отчёт о недостижимых состояниях и тупиках. |

**Существующий API:** `survpm.CensoredStateNet(start, terminal).fit(log)` строит и обучает сеть; `model.edges_table()` возвращает таблицу переходов; `model.to_pm4py()` экспортирует сеть Петри.

## 2. Вероятности и распределения переходов

**Вход:** сеть, обучающий журнал, признаки X, сведения о цензурировании и настройки распределений.

**Выход:** обученная модель, которая для состояния и X возвращает вероятности исходящих переходов и распределение времени каждого перехода.

| Функция | Вход → выход |
|---|---|
| `fit(log, graph, feature_spec, model_config)` | Данные, сеть и настройки → обученная модель и диагностика. |
| `transition_parameters(model, state, X)` | Состояние и признаки → вероятности и распределения исходящих переходов. |
| `parameters_table(model)` | Модель → таблицы вероятностей, распределений и коэффициентов признаков. |

Поддерживаются семейства exponential, Weibull, lognormal и gamma; интерфейс допускает другие распределения. Незавершённые наблюдения учитываются как правое цензурирование.

**Существующий API:** `CensoredStateNet(..., feature_columns=[...]).fit(log)`, `model.for_features(values)`, `model.edges_table()`, `model.coefficients_table()`. `for_features` задаёт фиксированный профиль признаков; целевой цикл ниже использует значения X при каждом входе в состояние.

## 3. Генерация

**Вход:** обученная или заданная вручную модель, начальное состояние, начальные X и абсолютное время, функция обновления X, число объектов, горизонт и `seed`.

**Выход:** синтетический журнал с `case_id`, состоянием, абсолютным временем входа и X для каждого посещения; сведения о завершении или остановке траектории.

### Цикл генерации и применения

1. Объект входит в состояние `state` в абсолютный момент `t`.
2. `X = update_features(old_X, state, t)` возвращает новые значения признаков.
3. В журнал записываются `case_id`, `state`, `t` и обновлённые X.
4. По `state` и X вычисляются вероятности и распределения времени всех исходящих переходов.
5. `sample_transition(probabilities, distributions, rng)` выбирает направление по вероятностям и длительность из распределения выбранного перехода.
6. Время увеличивается на выбранную длительность; объект входит в следующее состояние, и цикл повторяется до конечного состояния или другого условия остановки.

X обновляется **только при входе в состояние**. Замер, поступивший во время ожидания, учитывается при следующем входе; выбранные переход и время ожидания не пересчитываются.

| Функция | Вход → выход |
|---|---|
| `simulate(model, initial, update_features, n, horizon, seed)` | Модель и начальные условия → сгенерированные траектории с X, состояниями и временем. |
| `sample_transition(probabilities, distributions, rng)` | Вероятности и распределения → следующее состояние и длительность ожидания. |
| `update_features(old_X, state, t)` | Предыдущие X, состояние и абсолютное время → новые X. Для генерации задаётся пользователем или моделью признаков. |

**Существующий API:** `model.simulate(n, seed, censoring, horizon)` возвращает пары `(states, times)`; `survpm.simulate(edges, start, terminal, n, ...)` генерирует по заданным рёбрам; `survpm.traces_to_log(traces, entries)` преобразует трассы в журнал событий. Общий цикл с обновлением и записью X — целевой контракт.

## 4. Применение к реальным данным

**Вход:** обученная модель, объект, история его состояний и измерений, момент применения и правило получения признаков.

**Выход:** признаки объекта на заданный момент и результат применения модели: вероятности, распределения, продолжение траектории или прогноз.

Для реальных данных `update_features(old_X, state, t)` возвращает значения, доступные к абсолютному моменту `t`: по умолчанию последнее измерение каждого признака не позже `t`. При отсутствии замера действует заданное правило пропусков. Возможны фиксированный профиль X и меняющиеся во времени данные X(t); в обоих случаях цикл считывает X при входе в состояние.

| Функция | Вход → выход |
|---|---|
| `make_context(log, case_id, as_of)` | История объекта и момент времени → состояние, время входа, доступные X и история. |
| `update_features(old_X, state, t)` | Контекст и реальная история измерений → X на абсолютный момент `t`. |

**Существующий API:** `features.values_at(points, log, ...)` возвращает последние доступные признаки на заданные моменты; `features.at_entry(intervals, log, ...)` — признаки на входе в состояния; `features.split(...)` делит интервалы по моментам измерений. Подключение этих значений к циклу генерации — целевой контракт.

## 5. Прогноз

**Вход:** обученная модель, текущее состояние объекта, время входа, доступные признаки и история, горизонты прогноза и правило будущих X.

**Выход:** вероятности переходов и исходов, распределение оставшегося времени, прогнозные состояния или траектории.

| Функция | Вход → выход |
|---|---|
| `predict_next(model, context, horizons)` | Контекст → вероятности следующего перехода к заданным горизонтам. |
| `predict_time(model, context, targets, horizons)` | Контекст и целевые состояния → распределение оставшегося времени до исхода. |
| `predict_outcomes(model, context, horizons)` | Контекст → вероятность каждого конечного исхода к горизонту. |
| `predict_states(model, context, horizons)` | Контекст → вероятности находиться в разных состояниях в заданные моменты. |
| `predict_paths(model, context, horizon, n, seed)` | Контекст → возможные продолжения траектории и их частоты. |

Горизонты отсчитываются от момента прогноза. Для расчётов по симуляциям возвращаются сгенерированные времена и оценённое распределение; KDE может использоваться для отображения плотности.

**Существующий API:** `model.survival(t)` — время до исхода от начала процесса; `model.residual_survival(state, elapsed, t)` — оставшееся время из текущего состояния с учётом прошедшего ожидания; `model.state_curves(horizon)` — кривые по состояниям; `model.completion_times(n, seed)` — времена завершения по симуляции. Для модели с признаками профиль задаётся через `model.for_features(values)`.

## 6. Визуализация

**Вход:** сеть, таблицы параметров, реальные или сгенерированные данные, результаты прогноза и метрик.

**Выход:** граф сети или график, доступный для показа и сохранения.

| Функция | Вход → выход |
|---|---|
| `plot_graph(graph, model)` | Сеть и параметры → схема состояний и переходов. |
| `plot_survival(prediction)` | Прогноз времени → кривые выживаемости. |
| `plot_transitions(prediction)` | Прогноз → вероятности переходов или исходов. |
| `plot_measurements(log, case_id)` | Измерения объекта → временные ряды X. |
| `plot_comparison(real_log, simulated_log)` | Два журнала → сравнение распределений. |

**Существующий API:** `survpm.viz.state_graph(...)` строит схему сети; `survpm.adapters.draw_state_net(...)` визуализирует сеть Петри.

## 7. Score: метрики и оценка

**Вход:** обученная модель, отложенные реальные данные, сгенерированные данные или прогнозы, список метрик и настройки оценки.

**Выход:** таблицы значений метрик по моделям, объектам оценки и при необходимости фолдам; размер выборки и сведения о цензурировании.

| Что оценивается | Примеры метрик |
|---|---|
| Сеть | Fitness, precision, generalization, simplicity; совпадение состояний и переходов. |
| Траектории | Различия распределений путей и частот переходов. |
| Время | Различия длительностей и кривых выживаемости. |
| Вероятностная модель | Отрицательное логарифмическое правдоподобие с цензурой, доля неизвестных переходов. |
| Прогноз | Brier score, integrated Brier score, калибровка по горизонтам. |
| Измерения | Сходство распределений X и интервалов между замерами. |

| Функция | Вход → выход |
|---|---|
| `evaluate(model, test_log, metrics)` | Модель и тестовый журнал → таблицы метрик. |
| `compare_logs(real_log, simulated_log, metrics)` | Реальный и сгенерированный журналы → показатели сходства. |
| `compare_graphs(reference, estimated, metrics)` | Две сети и соответствие состояний → совпадающие и различающиеся переходы, показатели сходства. |
| `cross_validate(log, model_config, metrics, folds)` | Журнал и настройки → метрики по фолдам и итоговая сводка. |

Обучение и оценка используют разные объекты; преобразования признаков и оценки для учёта цензурирования строятся на обучающей выборке.

**Существующий API:** `model.evaluate(...)`, `model.nll(...)`, `survpm.metrics.crossval.CrossValidator(...).add_metrics(...).run(...)`, `crossval.cross_validate(...)`.
